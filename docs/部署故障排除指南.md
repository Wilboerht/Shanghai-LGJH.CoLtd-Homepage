# 部署故障排除指南

## 🚨 Prisma网络连接问题

### 问题描述

在服务器部署时出现以下错误：

```
Error: request to https://binaries.prisma.sh/all_commits/xxx failed, reason: getaddrinfo EAI_AGAIN binaries.prisma.sh
```

### 原因分析

1. **网络连接问题**: 服务器无法访问Prisma的CDN
2. **DNS解析失败**: 无法解析binaries.prisma.sh域名
3. **防火墙限制**: 企业网络可能阻止外部连接
4. **配置过时**: package.json中的prisma配置已弃用

## 🛠️ 解决方案

### 方案1: 使用国内镜像（推荐）

#### 1.1 设置环境变量

```bash
# Linux/Mac
export PRISMA_ENGINES_MIRROR="https://registry.npmmirror.com/-/binary/prisma/"
export PRISMA_CLI_BINARY_TARGETS="native"

# Windows
set PRISMA_ENGINES_MIRROR=https://registry.npmmirror.com/-/binary/prisma/
set PRISMA_CLI_BINARY_TARGETS=native
```

#### 1.2 使用部署脚本

```bash
# Linux/Mac
bash scripts/deploy-fix.sh

# Windows
scripts\deploy-fix.bat
```

### 方案2: 离线部署

#### 2.1 预下载Prisma引擎

在有网络的环境中：

```bash
# 下载所需的引擎文件
npx prisma generate
# 打包node_modules/.prisma目录
tar -czf prisma-engines.tar.gz node_modules/.prisma
```

#### 2.2 服务器部署

```bash
# 解压引擎文件
tar -xzf prisma-engines.tar.gz
# 设置离线模式
export PRISMA_SKIP_POSTINSTALL_GENERATE=true
npm install
npm run build
```

### 方案3: 使用代理

#### 3.1 配置HTTP代理

```bash
export HTTP_PROXY=http://proxy.company.com:8080
export HTTPS_PROXY=http://proxy.company.com:8080
npm run db:generate
```

#### 3.2 配置NPM代理

```bash
npm config set proxy http://proxy.company.com:8080
npm config set https-proxy http://proxy.company.com:8080
npm config set registry https://registry.npmmirror.com
```

## 🚀 自动化部署脚本

### 创建部署脚本

```bash
#!/bin/bash
# deploy.sh

set -e  # 遇到错误立即退出

echo "🚀 开始自动化部署..."

# 1. 环境检查
if ! command -v node &> /dev/null; then
    echo "❌ Node.js 未安装"
    exit 1
fi

# 2. 设置镜像
export PRISMA_ENGINES_MIRROR="https://registry.npmmirror.com/-/binary/prisma/"
export NPM_CONFIG_REGISTRY="https://registry.npmmirror.com"

# 3. 安装依赖
echo "📦 安装依赖..."
npm ci --production=false

# 4. 数据库设置
echo "🗄️ 设置数据库..."
npx prisma generate
npx prisma migrate deploy

# 5. 构建项目
echo "🏗️ 构建项目..."
npm run build

# 6. 启动服务
echo "🎉 部署完成，启动服务..."
npm start
```

### 使用Docker部署

```dockerfile
# Dockerfile
FROM node:18-alpine

WORKDIR /app

# 设置Prisma镜像
ENV PRISMA_ENGINES_MIRROR=https://registry.npmmirror.com/-/binary/prisma/

# 复制package文件
COPY package*.json ./
COPY prisma ./prisma/

# 安装依赖
RUN npm ci --only=production

# 生成Prisma客户端
RUN npx prisma generate

# 复制源代码
COPY . .

# 构建项目
RUN npm run build

EXPOSE 3100

CMD ["npm", "start"]
```

## 🚨 API认证和用户管理问题

### 问题描述

部署后出现以下错误：

- `405 Method Not Allowed` - API路由无法访问
- `SyntaxError: Unexpected token '<'` - API返回HTML而不是JSON
- 用户无法创建、删除、修改密码
- 系统状态API失败

### 错误分析

这些错误通常表明：

1. **NextAuth配置问题** - 认证中间件无法正常工作
2. **环境变量缺失** - NEXTAUTH_SECRET等关键配置缺失
3. **API路由被重定向** - 请求被重定向到登录页面
4. **会话管理问题** - 用户会话无法正确验证

### 解决方案

#### 方案1: 使用自动修复脚本（推荐）

```bash
# Windows
scripts\fix-production-env.bat

# Linux/Mac
bash scripts/fix-production-env.sh
```

#### 方案2: 手动修复步骤

##### 1. 检查和修复环境变量

```bash
# 创建.env.local文件
cat > .env.local << EOF
NODE_ENV=production
DATABASE_URL="file:./dev.db"
NEXTAUTH_URL=http://localhost:3100
NEXTAUTH_SECRET="$(openssl rand -base64 32)"
DOCKER_BUILD=false
EOF
```

##### 2. 重新生成和构建

```bash
# 清理缓存
rm -rf .next node_modules/.cache

# 重新生成Prisma客户端
npx prisma generate

# 重新构建
npm run build
```

##### 3. 使用正确的启动命令

```bash
# 使用生产环境启动脚本
npm run start:production

# 而不是
npm start  # 这可能会有standalone配置冲突
```

#### 方案3: 诊断工具

```bash
# 运行诊断脚本
node scripts/diagnose-api-issues.js
```

### 验证修复效果

1. **检查API响应**

   ```bash
   curl -I http://localhost:3100/api/admin/system/status
   ```

   应该返回403 Forbidden（需要认证）而不是405 Method Not Allowed

2. **检查登录功能**
   - 访问 `/admin/login`
   - 使用管理员账号登录
   - 检查是否能正常访问用户管理页面

3. **检查用户管理功能**
   - 创建新用户
   - 修改用户信息
   - 删除用户

## 🔧 Next.js Standalone配置问题

### 问题描述

启动时出现警告：`"next start" does not work with "output: standalone" configuration`

### 解决方案

#### 方案1: 使用条件配置（推荐）

已修改`next.config.ts`，根据环境变量决定是否启用standalone模式：

```typescript
output: process.env.DOCKER_BUILD === 'true' ? 'standalone' : undefined,
```

#### 方案2: 使用不同的启动命令

```bash
# 普通部署
npm run start:production

# Docker部署
npm run start:standalone
```

### 新增的启动脚本

- `start:production`: 生产环境启动（不使用standalone）
- `start:standalone`: Docker环境启动（使用standalone）
